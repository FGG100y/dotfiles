# 成批指出项目中文本或者代码的位置

## 何时启用

- 用户要求**成批**指出代码或文本位置：校验文档、调用链、多处修改点、**Sphinx/.rst 校对清单**等。
- 用户 **@** 本技能名，或消息里出现 **refer-to-code**、**quickfix**、**位置文件** 时，按本技能执行。

### 路径与命名（默认）

1. **目录**：仅 `{workspace_root}/`，**不要**默认写到 `.cursor/` 或其它子目录（除非用户指定）。
2. **文件名**：使用“LOC-”开头，后面根据具体的用途选择合理的英文名。
   **默认模式**：`LOC-name-{YYYYMMDD-HHMMSS}.txt`  
   示例：`LOC-proofread-to-model-a-20260331-143052.txt`
3. **禁止覆盖**：每次执行都生成**新文件名**；**不得**把结果写进固定名（如总是 `quickfix.txt`）以致冲掉上一次。若同一秒内生成两次（极少见），在时间戳后再加 `-2`、`-3` 或短随机后缀。
4. **用户指定**：若用户给出文件名或相对项目根的路径（如 `notes/review-foo.txt`），以用户为准；若用户只给了基名而无时间戳，仍建议**追加当前时间戳** unless 用户明确说「就覆盖这个文件」。
5. **文件内路径**：每条中的源文件路径 **相对项目根**，正斜杠。

### 回复里写什么

- **完整相对路径**（从项目根起）：如 `LOC-proofread-to-model-a-20260331-143052.txt`。
- **条目数量**、如何配合 vim/quickfix 打开（见下）。
- **不要**在聊天里重复贴全文；最多 **3～5 行** 样例。

## 行格式

每行一条，**行首无缩进**：

```
相对项目根的路径:行号:列号: 级别: 说明
```

- **列号**：无则 `1`。  
- **级别**：`error` / `warn` / `info` 等。

示例：

```
软件构架设计/README.rst:336:1: info: 体例: 「成份」是否改为「成分」
```

## vim / quickfix 提示（可写在回复里）

- 在项目根：`:cfile LOC-proofread-to-xxx-md-YYYYMMDD-HHMMSS.txt` 再 `:copen`（依本地 `errorformat` 调整）。  
- 文件前几行可用 `#` 注释说明格式与生成时间（注释行是否参与解析取决于用户 `efm`，多数配置会忽略不匹配行或可手动删）。

## 与表格、代码引用的关系

- 表格只作补充；**完整清单以本次生成的磁盘文件为准**。

## 版本控制

- 此类文件多为本地校对记录，建议在项目 `.gitignore` 中加入一条，例如：`LOC-*.txt`（**仅在用户希望忽略时**由用户或 Agent 按需添加，勿擅自大改 `.gitignore`）。
